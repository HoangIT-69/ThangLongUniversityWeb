📊 00. Tổng Quan Dự Án

Phạm vi, cấu trúc dự án và danh sách các modules nghiệp vụ cốt lõi.

Mục Tiêu & Phạm Vi Nghiệp Vụ

Hệ thống được thiết kế nhằm tin học hóa và tối ưu hóa toàn diện các quy trình quản lý đào tạo tín chỉ tại Trường Đại học Thăng Long. Trọng tâm của dự án là giải quyết vấn đề nghẽn mạng nghiêm trọng khi hàng ngàn sinh viên đăng ký học phần cùng một thời điểm bằng cách áp dụng cơ chế xếp hàng bất đồng bộ qua Message Broker Apache Kafka. Hệ thống cũng tích hợp quy trình thanh toán học phí qua cổng VNPay, chatbot thông minh hỗ trợ sinh viên dựa trên cơ sở tri thức (RAG), và module chat trực tiếp thời gian thực.

Kiến Trúc & Phân Lớp Kỹ Thuật

Kiến trúc dự án tuân thủ mô hình Layered Architecture (Kiến trúc phân lớp):

  • Frontend: React 19, TypeScript, TanStack Router để quản lý định tuyến, TanStack Query để caching dữ liệu, và TailwindCSS kết hợp Radix UI (Shadcn/UI).
  • Backend: Java 17, Spring Boot 3.x, Spring Security (JWT authentication), JPA/Hibernate.
  • Hạ tầng & CSDL: CSDL PostgreSQL lưu trữ dữ liệu bền vững, Redis lưu trữ cache và Token Blacklist, Apache Kafka lưu trữ hàng đợi đăng ký.

💼 01. Phân Tích Nghiệp Vụ

Tác nhân hệ thống, quyền truy cập và các luật nghiệp vụ chính.

👑

Quản Trị Viên (Admin)

ADMIN

Chịu trách nhiệm quản trị hệ thống, quản lý cơ sở dữ liệu nền (Môn học, học kỳ, lớp niên chế, sinh viên, giảng viên), xếp lịch thi, cấu hình trạng thái đóng/mở cổng đăng ký học phần, đăng ký thi lại, quản lý hóa đơn học phí và nạp tri thức cho AI Chatbot.

👨‍🏫

Giảng Viên (Teacher)

TEACHER

Quản lý các lớp học phần được phân công giảng dạy: ghi nhận điểm danh sinh viên vắng/muộn cho từng buổi học, nhập điểm thành phần chuyên cần (10%), giữa kỳ (30%), cuối kỳ (60%), thực hiện khóa điểm số để ngăn chặn chỉnh sửa trái phép.

👨‍🎓

Sinh Viên (Student)

STUDENT

Tra cứu thông tin cá nhân, thời khóa biểu và lịch thi; thực hiện đăng ký lớp học phần trực tuyến, đăng ký thi lại / học cải thiện điểm; kiểm tra hóa đơn và thanh toán học phí qua VNPay; trao đổi bài học qua chat trực tuyến và hỏi đáp quy chế tự động với Chatbot AI.

⚙️ 03. Yêu Cầu Chức Năng (FR) Chi Tiết

Đặc tả chi tiết các yêu cầu chức năng cốt lõi của hệ thống.

FR-035 — Đăng ký học phần bất đồng bộ qua Kafka

Mô tả: Xử lý đăng ký học phần tập trung dưới dạng hàng đợi giúp hệ thống không bị crash CSDL khi quá tải.

  • Actor: STUDENT
  • Input: classSectionId (ID lớp học phần muốn đăng ký)
  • Output: requestId (Mã yêu cầu đăng ký học phần), Trạng thái xử lý PENDING
  • Luồng xử lý chính:
    1. Sinh viên chọn lớp học phần trên giao diện đăng ký học phần.
    2. Frontend gọi API POST /api/student/enroll/{classSectionId}.
    3. Backend (Spring Boot) đẩy thông điệp request chứa mã sinh viên và mã lớp học phần vào Kafka Topic enrollment-requests, đồng thời ghi nhận một bản ghi trạng thái yêu cầu vào bộ nhớ Redis / Database với status là PENDING.
    4. Hệ thống trả ngay phản hồi 202 Accepted về cho Frontend kèm theo requestId, giúp giải phóng kết nối HTTP ngay lập tức.
    5. Bộ tiêu thụ tin nhắn (Kafka Consumer) đọc bất đồng bộ thông điệp từ hàng đợi, thực hiện tuần tự việc kiểm tra luật nghiệp vụ (Trùng lịch, kiểm tra môn học tiên quyết, kiểm tra slot lớp học phần).
    6. Nếu thỏa mãn, tiến hành cập nhật số lượng slot lớp học phần và ghi nhận bản ghi đăng ký vào bảng enrollments trong giao dịch PostgreSQL an toàn. Đánh dấu trạng thái yêu cầu là SUCCESS. Nếu thất bại, ghi nhận trạng thái FAILED kèm lý do lỗi chi tiết.
    7. Frontend thực hiện Polling gọi API GET /api/student/enrollments/status/{requestId} mỗi 2 giây một lần để lấy trạng thái xử lý và hiển thị thông báo thành công/thất bại trực quan cho sinh viên.
  • Luồng ngoại lệ: Lớp học phần đầy slot, lớp học phần bị trùng lịch biểu trong thời khóa biểu hiện tại của sinh viên, sinh viên chưa tích lũy đủ môn học tiên quyết, hoặc kỳ đăng ký học phần đã bị đóng bởi Admin.
  • API liên quan: POST /api/student/enroll/{classSectionId}, GET /api/student/enrollments/status/{requestId}
  • Bảng CSDL liên quan: students, class_sections, enrollments

FR-062 — Thanh toán học phí trực tuyến qua VNPay NCB Sandbox

Mô tả: Cung cấp kênh thanh toán học phí tiện dụng, an toàn qua cổng VNPay.

  • Actor: STUDENT
  • Input: semesterId (ID học kỳ cần thanh toán học phí)
  • Output: Redirect URL (Đường link redirect sang giao diện thanh toán an toàn của VNPay)
  • Luồng xử lý chính:
    1. Sinh viên truy cập màn hình học phí, bấm nút "Thanh toán học phí" cho học kỳ hiện tại.
    2. Frontend gọi API POST /api/student/tuition/{semesterId}/vnpay-url.
    3. Backend tìm hóa đơn học phí tương ứng trong bảng tuition_bills, tính toán số tiền cần nộp, tạo mã giao dịch duy nhất txn_ref và gửi request ký số SHA512 bảo mật để tạo URL redirect sang cổng VNPay NCB Sandbox. Trả URL này về cho Frontend.
    4. Frontend redirect sinh viên sang cổng thanh toán VNPay. Sinh viên nhập thông tin thẻ ATM Test của NCB.
    5. Sau khi thanh toán xong, VNPay redirect sinh viên quay lại trang Frontend của hệ thống kèm theo tham số chữ ký bảo mật /student/payment-result?vnp_ResponseCode=....
    6. Frontend gọi API Callback GET /api/payment/vnpay-callback để Backend kiểm tra tính toàn vẹn của chữ ký số (VNP Secure Hash).
    7. Nếu chữ ký hợp lệ và mã trả về là 00 (Thành công), Backend cập nhật hóa đơn học phí thành Đã thanh toán (is_completed = true), tạo bản ghi lịch sử giao dịch vào bảng payment_transactions. Giao diện hiển thị thông báo thành công cho sinh viên.
  • Luồng ngoại lệ: Chữ ký bảo mật VNPay không hợp lệ (nghi ngờ giả mạo request), sinh viên hủy giao dịch tại cổng VNPay, hoặc số tiền giao dịch bị sai lệch so với hóa đơn học phí thực tế.
  • API liên quan: POST /api/student/tuition/{semesterId}/vnpay-url, GET /api/payment/vnpay-callback
  • Bảng CSDL liên quan: tuition_bills, payment_transactions

🔒 04. Yêu Cầu Phi Chức Năng (NFR)

Đặc tả các tiêu chuẩn kỹ thuật phi chức năng về bảo mật, hiệu năng chịu tải, caching và mở rộng hạ tầng.

🛡️ An Toàn & Bảo Mật Hệ Thống

  • BCrypt Password Hashing: Tất cả mật khẩu của người dùng bắt buộc phải được mã hóa trước khi lưu trữ xuống Postgres thông qua giải thuật BCryptPasswordEncoder với độ muối an toàn.
  • Role-Based Access Control (RBAC): Bảo vệ nghiêm ngặt từng đầu REST API bằng Spring Security và annotation @PreAuthorize("hasRole('STUDENT')") hoặc @PreAuthorize("hasRole('ADMIN')") để tránh lỗ hổng phân quyền ngang IDOR.
  • JWT Blacklist: Khi người dùng thực hiện đăng xuất, Refresh Token sẽ bị thu hồi và Access Token tương ứng sẽ bị đưa vào Token Blacklist được lưu trên Redis với thời gian hết hạn (TTL) bằng thời hạn của token để ngăn chặn tái sử dụng token.

⚡ Hiệu Năng & Khả Năng Chịu Tải

  • Kafka Message Broker: Cơ chế bất đồng bộ giúp bảo vệ CSDL PostgreSQL khỏi nghẽn luồng kết nối kết nối (connection pool) khi có trên 5,000 lượt request đăng ký học phần đồng thời.
  • Redis Caching Layer: Các truy vấn nặng ít biến động (như Danh sách môn học, Danh sách học kỳ, Danh mục ngành) được lưu trên Redis để giảm thời gian phản hồi API xuống dưới 50ms.
  • Optimized Indexes: Tận dụng các index đã thiết lập trên PostgreSQL (như idx_enrollments_student_id, idx_css_day_period) để tối ưu hóa hiệu năng truy vấn thông tin thời khóa biểu sinh viên và nhập điểm của giảng viên.
