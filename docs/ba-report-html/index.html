📊 00. Tổng Quan Dự Án

Phạm vi, cấu trúc dự án và danh sách các modules nghiệp vụ cốt lõi.

Mục Tiêu & Phạm Vi

Hệ thống được thiết kế nhằm hiện đại hóa quy trình học vụ tại Trường Đại học Thăng Long, giải quyết bài toán tải cao khi đăng ký học phần tập trung, tự động hóa tính toán điểm GPA/CPA, cung cấp cổng thanh toán trực tuyến bảo mật và hỗ trợ giải đáp thông tin tự động qua Chatbot AI.

Kiến Trúc Hệ Thống

Hệ thống sử dụng mô hình Layered Architecture 4 lớp cho Backend (Spring Boot), Single Page Application (React) cho Frontend, giao tiếp thông qua RESTful APIs và WebSocket. Hệ thống xử lý hàng đợi qua Apache Kafka và lưu trữ cache qua Redis.

Luật Nghiệp Vụ Cốt Lõi (Business Rules)

BR-01
Công thức điểm tích lũy: Điểm HP = CD×0.1 + GK×0.3 + CK×0.6. Điểm chữ quy đổi tự động (A, B, C, D, F).
BR-02
Điều kiện thi lại (RETAKE): Sinh viên bị điểm F (<4.0) bắt buộc phải đăng ký thi lại trong học kỳ mở retake.
BR-03
Khóa điểm (Grade Locking): Bảng điểm lớp HP sau khi được Giảng viên ấn "Khóa" sẽ không thể chỉnh sửa trừ khi có yêu cầu đặc biệt gửi Admin.
BR-04
Ràng buộc Đăng ký HP: Phải trong học kỳ mở đăng ký, lớp học phần còn slot trống, sinh viên không bị trùng lịch học/lịch thi và đạt môn tiên quyết.

🔒 03. Yêu Cầu Phi Chức Năng (NFR)

Tiêu chuẩn phi chức năng về hiệu năng, bảo mật và khả năng mở rộng.

🛡️ Bảo Mật & Xác Thực

  • JWT authentication: Token ngắn hạn kèm Refresh Token rotation được quản lý trong Redis để hủy token khi logout.
  • Mã hóa mật khẩu: Hash mật khẩu bằng BCrypt.
  • RBAC Phân quyền: Bảo vệ API ở cấp độ Spring Security @PreAuthorize.

⚡ Hiệu Năng & Tải Cao

  • Kafka Queue: Đăng ký học phần xử lý bất đồng bộ, chịu tải >5000 requests/giây mà không treo DB.
  • Caching: Dùng Redis lưu trữ cache session, JWT blacklist và thông tin ít thay đổi.
  • Index CSDL: Thiết lập INDEX trên các khóa ngoại hay query (student_id, class_section_id).

🔄 Tính Khả Dụng & Mở Rộng

  • Docker Compose: Đóng gói độc lập toàn bộ hạ tầng (Postgres, Redis, Kafka, Spring Boot).
  • API RESTful chuẩn: Dễ dàng scale theo chiều ngang (Horizontal Scaling) bằng cách nhân bản instances.
  • TanStack Query: Caching phía client, hạn chế gọi API trùng lặp.

Các Thực Thể Quan Trọng Nhất

Hệ thống bao gồm 22 bảng cơ sở dữ liệu. Bảng users đóng vai trò lưu tài khoản đăng nhập và được mở rộng 1-1 qua bảng students hoặc teachers. Mối quan hệ giữa sinh viên và lớp học phần được thể hiện qua thực thể trung gian enrollments. Bảng grades lưu kết quả điểm số và liên kết 1-1 với enrollments, giúp phân tách rõ ràng lịch sử đăng ký học phần và kết quả điểm số.

💡 10. Đánh Giá & Đề Xuất Cải Tiến

Phân tích điểm mạnh, điểm yếu hiện tại và lộ trình phát triển tối ưu hệ thống.
